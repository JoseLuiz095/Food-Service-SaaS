FOODWEB v0.5.4 - PARIDADE VISUAL COM FLORIWEB + REPARO DE INTERACOES

OBJETIVO
- Replicar no Admin e Admin Master do FoodWeb o mesmo design system do FloriWeb.
- Manter a identidade FoodWeb com paleta quente ligada a alimentacao.
- Corrigir a integracao de INTERACOES quando a RPC food_platform_list_event_log_v1 ainda nao existe no Supabase.
- Ajustar o avatar/perfil do topo para remover o fundo excessivamente claro.

CORRECAO DA AREA INTERACOES
O erro "Could not find the function public.food_platform_list_event_log_v1... in the schema cache"
significa que a parte de telemetria da migration v0.5.0 nao esta disponivel no banco atual.

Foi incluido um reparo SQL idempotente e restrito a objetos food_* de telemetria:
  SUPABASE_INTERACOES_V054.sql

Ele cria/atualiza somente:
- public.food_platform_event_log
- public.food_log_platform_event_v1(...)
- public.food_platform_list_event_log_v1(...)
- indices e permissoes relacionados
- reload do schema do PostgREST

Nao altera planos, valores, pedidos, financeiro, credenciais ou tabelas do FloriWeb.

PASSO OBRIGATORIO NO SUPABASE
1. Abra o SQL Editor do projeto Supabase usado pelo FoodWeb.
2. Execute SUPABASE_INTERACOES_V054.sql.
3. Execute VALIDAR_INTERACOES_V054.sql.
4. Na primeira consulta, confirme:
   tabela_eventos_ok = true
   rpc_gravar_evento_ok = true
   rpc_listar_eventos_ok = true
5. Volte ao Admin Master > Diagnostico e clique em "Executar novamente".

ALTERACOES VISUAIS
- Mesma estrutura de sidebar do FloriWeb.
- Mesma organizacao por Operacao / Catalogo / Gestao / Conta.
- Mesmo padrao de topbar, status da loja e mensalidade.

- Mesmo padrao de Admin Master.

TELA DE INTERACOES
- Texto de privacidade alinhado ao FloriWeb.
- Quando a RPC estiver ausente, nao mostra mais a assinatura tecnica bruta ao usuario.
- A tela orienta diretamente qual SQL executar.
- Com a RPC instalada, volta a exibir Falhas recentes, Interacoes sem conclusao e Auditoria critica.
