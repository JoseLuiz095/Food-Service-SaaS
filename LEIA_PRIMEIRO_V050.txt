FoodWeb v0.5.0 - Estabilidade e cobranca

PRE-REQUISITO
- Projeto atual em v0.4.9.
- O .env atual deve continuar na raiz.

COMO APLICAR
1. Extraia TODO este ZIP diretamente na raiz atual do FoodWeb.
2. Execute APLICAR_V050_NA_RAIZ.bat.
3. No Supabase SQL Editor execute:
   supabase\migrations\202609151040_foodweb_v050_stability_billing_audit.sql
4. Execute no SQL Editor:
   supabase\VALIDAR_V050.sql
5. Se a validacao estiver correta, execute PUBLICAR_V050.bat.

PRINCIPAIS ALTERACOES
- Botao explicito Confirmar renovacao e Nao confirmar renovacao.
- Decisao separada para alteracao de plano.
- Centro de pendencias no Admin Master.
- Diagnostico de falhas, interacoes sem conclusao e auditoria critica.
- Registro de erros globais sem armazenar senha/token/documento.
- Vencimento aceita dias 1..31; fevereiro usa o ultimo dia sem alterar o due_day configurado.
- Status de mensalidade centralizado nas telas.
- OCR reaproveita worker durante a sessao e destaca campos reconhecidos.
- Financeiro mostra origem manual/pedido/ajuste e link para Pedidos.
- Edge Function de credenciais registra auditoria segura.

PRESERVADO
- .env / .env.local / .env.production
- wrangler.jsonc
- supabase\config.toml
- .git
- Turnstile e secrets existentes
- Dados atuais dos clientes

O patch cria backup local em _backup_food_v050 antes de substituir os arquivos.
